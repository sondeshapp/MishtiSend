# Contributing to FlashSend 🚀

We love your input! We want to make contributing to FlashSend as easy and transparent as possible, whether it's:

- Reporting a bug
- Discussing the current state of the code
- Submitting a fix
- Proposing new features
- Becoming a maintainer

## 🛠️ Development Workflow

1. **Fork the repo** and create your branch from `main`.
2. **Setup environment**: Run `npm install` in both `frontend/` and `server/`.
3. **Make changes**: If you've added code that should be tested, add tests.
4. **Link to issue**: If your PR fixes an open issue, link to it.
5. **Quality check**: Ensure your code linting passes (`npm run lint`).
6. **Submit PR**: Describe your changes in detail in the PR description.

## 📜 Coding Style

- Use **TypeScript** for all frontend logic.
- Use **functional components** and hooks for React.
- Follow the existing **CSS variable** design system for any UI changes.
- Ensure all new features are compatible with WebRTC standards.

## 🐞 Reporting Bugs

- Use a clear and descriptive title for the issue.
- Describe the exact steps which reproduce the problem.
- Provide snapshots or logs if possible.

## 💡 Feature Requests

- Explain why this feature would be useful.
- Provide examples of how it would work.
- If it's a UI change, a rough mock-up is appreciated!

Thank you for helping make FlashSend better! 🌟
